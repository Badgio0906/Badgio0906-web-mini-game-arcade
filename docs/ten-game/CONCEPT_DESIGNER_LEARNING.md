## 何を学ぶか

プレイヤーが最初に「何をするか」を理解し、操作を楽しみ、上達した結果として予想外の先を見る構造を考える。笑いだけの小品を数で増やすことを目標にしない。

1. 普通の日常状況を一つ選ぶ。通勤、駐車、給湯室、事務机、会議など、数秒で目的が想像できるもの。
2. その状況を1〜2種類の主操作へ変える。入力種類を増やす代わりに、一つの操作が結果へどう影響するかを深くする。
3. 上達できるSkillを一つ以上作る。精度、慣性予測、先読み、記憶、視覚探索、資源管理、危険判断など。押すだけで結果がランダムならSkillにならない。
4. Scoreの意味を明確にする。運んだ、積んだ、保った、見つけた等、プレイヤーが結果と改善を結び付けられる単位を主にする。
5. 「普通ならここで終わり」という地点を候補として置く。仕事場への到着、十分な駐車成功、予定の会議終了など。
6. 得点を確定する安全な終了、普通の条件を保つ選択、危険な続行の余地を検討する。単に「続けなければ損」と感じる選択にしない。
7. 続行した到達者だけが見る体験を作る。新しい身体負担、別の判断、舞台の意味の変化、異常な物量など。Score倍率だけを上げて済ませない。
8. Resultにも短い笑いを残す。具体的な状況に合う称号やコメントで「次は何と言われるか」を楽しめるようにする。

これは発想の候補であり、全ゲームへの強制テンプレートではない。Game001/004のように通常のSkill追求だけで成立するゲームへ、不要な選択画面や物語を足さない。安全選択は終了に限らず、通常建築を保つ、杯を増やさない、机を片付ける等でも成立する。意味の薄いmilestoneを全ゲームへ同じ秒数で配置しない。

## 楽しさと笑いの順番

目標は「最初は普通に面白い→上達する→先へ進む→何これ、と少し笑う」。最初の10秒に必要なのは読みやすい操作と気持ちよい反応。設定説明を先に長く読ませたり、ギャグで失敗原因を隠したりしない。

笑いの対象は状況・規模・会社の無茶・妙な肩書に置く。人の怪我、実在国・民族・政治家、実会社のロゴを面白さの代わりに使わない。Game003のC国は架空モードで、現実の国旗や人物へ接続しない。変な見た目でも、反応可能な予告、読める目標、正確なhit、速いRetryを優先する。

## 実装と独立レビューから得た具体的な学び

006の進行は`angle / power / driving / parked / choice / ended`の6状態。地図は直進、左右25度、狭い左右40度、左右90度縦列の7種類を成功数で解放する。状態数と経路数を混同しない。入力種類を増やさず、角度の解釈と車の収まりを変えている。42×70の車の四隅で成功を判定し、50×82の禁断枠は実際に余裕が小さい。車の生成絵が豪華でも、区画・軌道・着地点と実矩形が違えばSkillの説明を壊す。

006ではmodel oracleが成功できても、初期の角度/Powerの止められる時間が短かったため周期を見直した。ここから学ぶのは「解が存在する」と「人が精度を練習できる」は別であること。狭い枠の難しさは、人間が原因を読めて次の入力を直せるかまで試す。現在のunitやoracleの成功を、人間の楽しさ・1CREDIT時間の実測として使わない。

006の実レビューで見つかったもう一つの問題は、曲線区画の弱Power失敗を『角度』と説明したこと。走行距離も最終方向を変えるため、最後の角度誤差だけでは最初の角度操作の失敗と分からない。修正は『選んだ角度が必要距離なら全車を収められるか』を先に見て、収められるなら不足/過大Powerと説明する。物理結果を変えず、次に何を直すかを正しく伝える。ConceptのFailure欄も終状態だけでなく、操作から原因へ結び付く説明まで設計する。この理由修正は2成功後の弱Power実失敗で独立再確認済み。最終Feel/Visualと、保持された旧FAILを含むQA複合証拠は別記録にする。

007では生のNEXTが次の実客になり、kg/行先/配達点と直近の降車を見せる。例えば序盤の3Fの240kgの箱は今のかごへ収まるが、断ると、4Fで65kgが降りた後に次の305kg・高価値の一組を運べる。『今入るから受諾』だけで解けず、空きをいつ何へ使うか考える余地がある。005の正しい属性分類との差はここにある。推奨・正解ラベルを付けず、必要な事実を読める形で出す。

007の450kgちょうどは合法で、超過はその入力時に終了する。判断時間切れは拒否であり、それ自体はGame Overではない。全員を断り続ければ進めても0点になる。配達と積載効率がScoreを作るため、単なる階数サバイバルとして企画し直さない。かごの人物絵は全情報の代わりではなく、小画面では先頭3個と残数、詳しいkg/行先は名簿に残す。生の将来情報を出す場合、画面を大きくするより情報の優先順位が重要になる。

## 「何でも2倍速」を避ける

今回にも速度変化を使う002/003/007/010がある。今後の企画でそれを標準解にしない。候補を既存の変化軸と比較する。

| 変化軸 | 今回の例 | 新企画で考える問い |
| --- | --- | --- |
| 行為/目的の意味が変わる | 002の出社から旅 | 通常の終点を越えると、プレイヤーは何をしている人になるか |
| 空間の余裕が減る | 006の禁断の枠 | 入力や数値だけでなく、読む空間に新しい責任が生まれるか |
| 同時対象・負担が増える | 008の2〜3杯 | 操作を増やさずに、注意を配る対象や慣性の関係が変わるか |
| 管理した状態が残る | 009の机/Clutter | 自分で危険を残し、その状態に報酬を見いだせるか |
| 将来の空きを予測する | 007の降車 | 即時の正解だけでなく、少し先の資源が判断を変えるか |
| 前兆への注意が変わる | 010の役員会 | 単なる短縮ではなく、何を見て何を捨てるかが変わるか |

速度倍率を選ぶなら、変わるSkill、見える状態、利益、失敗理由を別々に書く。「2倍速・2倍点だから特殊モード」で終わった案は再考する。006の狭い枠や008の追加杯を、同じグローバル速度上昇へ置き換えて個性を消さない。タイトルの大げささやpalette変更だけを独自性の説明にしない。

## Concept候補の必須フォーマット

タイトルだけの案は実装候補へ上げない。各候補に以下を埋める。数値未確定は未確定とし、どう試すかまで書く。

| 項目 | 必須内容 |
| --- | --- |
| 日常状況・5秒の理解 | 誰が、何を、どうすればよいか。最初の一操作で目的が伝わるか |
| Core Loop | 状況を見る→入力する→結果/報酬を見る→次へ、を具体的に。1RUNと一判断の区別 |
| PC / Mobile操作 | 主操作1〜2種類、押す/離す/保持の意味、44px操作、片手での理解、必要な例外 |
| Primary Skill | 練習で改善する技能と、その改善が目に見える場面。既存ゲームとの差 |
| Score | 主単位、二次値、何をすると伸びるか。自分の次の目標が分かるか |
| Failure / 公平性 | 正確な失敗条件、事前に読める予告、失敗理由の表示。ランダム即死を避ける方法 |
| Replay理由 | 再挑戦で試したい具体的な改善、自己ベスト、先の体験、結果称号。広告を見ることは理由にしない |
| Risk / Reward | 安全行動と危険行動の利益/損失。危険を選ぶ動機、安全選択も納得できる理由 |
| 通常の終点 / Escalation | 採用するか、不要か、その理由。到達地点、choice、不可逆性、変わる体験と明示する情報 |
| 1プレイ時間 / Tempo | 初心者/経験者の設計目標秒、一判断の時間、特殊到達の想定。設計値と実測を分ける |
| Visual / Art Mode | 世界観、主役、構図、字体・素材、PC/Mobileの優先情報。既存10本との差 |
| Generated / Code / Hybrid | 画像生成が役立つもの、正確なhit/文字/状態としてコードに残すもの、配信容量目標 |
| Comedy / Result | 状況に合う小さい笑い、称号/コメントの方向。操作や公平性を邪魔しない境界 |
| 重複確認 | もっとも近い既存2本、共有する要素と異なる判断・状態・失敗・見た目 |
| Prototypeで確かめること | 初10秒、Skillの手応え、1〜3回Retry、特殊選択、Mobile読取、独立GameFeel/Visual/QAの検証点 |

RUN時間はmanifestの`expected_run_seconds`と揃える。ただし目標値は人間の測定結果ではない。特殊到達のゲーム内時間とwallclock、pause時間を区別する。既存の数値をそのまま全ジャンルへコピーせず、1CREDITの密度と3回続けるテンポを試す。

## 重複確認と候補の選び方

Main/Concept担当は入力、判断、状態、失敗、報酬、Escalation、Artを別々に比較する。共通インターフェースを使うことと、同じ遊びを作ることを混同しない。

- 同じSkill・同じCore Loop・同じ失敗理由が近いなら、題材だけの変更では候補を通さない。
- 同じ操作でも、プレイヤーが見る情報や将来状態が違えば候補として検討できる。違いを一文で具体的に書けること。
- 006と003は両方Timing/空間だが、006は角度＋Powerで二次元の収まり、003は一度DROPして多段の支持/重心。新しい物理案はどちらに近いか確認する。
- 004と009は押す場所を選ぶが、004は時間順の記憶、009は今見えている個体探索。9マスや対象数変更だけでは差を作れない。
- 職場題材は今回多い。次の候補で同じ机・会議・会社員に戻るなら、判断と見た目の新しさを特に強く示す。
- 既存の街・工場・建築台・装置・駐車場・Elevator・Coffee前景・散乱机・会議室を無批判に複製しない。別のpaletteだけではArtの新しさにならない。
- 遊びのSkillと結び付かない特殊mode、選択を押すたびにしか見られない長い説明、押せば無条件に最高倍率になるchoiceは修正する。

候補が少ないときも、品質に届かない案を本数目標のために通さない。今回の制作手順はConcept→Art Director/Brief→画像生成・参照確認→Prototype/Gameplay実装→実際のGameFeel→実画面Visual→QA→人間プレイ。各判断を記録する。Brief/画像生成が本体実装に先行する手順を守り、画像だけが先に豪華で遊びが空になる状態を避ける。

## 評価・Data Analystへ渡す情報

将来の`milestone_reached`、`escalation_offered`、`escalation_accepted`、`safe_exit`に対応できるよう、Concept時点で地点とchoiceの名前を付ける。例えばcompany_1000m/journeyやsecond_coffee/accept。イベントが送れることを、選択率が高い証拠にしない。広告回数より、Retry、Skill改善、到達、選択の迷い、体験の増加を重視する。

新ゲームの人間A〜JにK〜Nを追加する。K「先をもう少し見たいか」、L「特殊modeを選ぶか迷う楽しさ」、M「受諾後さらに面白いか」、N「ネタが邪魔しないか」。自動oracleで最適判断をした到達は技術証跡で、人間のSkill/面白さ評価ではない。人間未実施は未実施と記録する。
