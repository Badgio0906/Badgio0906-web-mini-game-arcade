# 伏字ことば ～KANA GUESS～ / Game023

Candidate No.30. Rules `1`, presentation `prototype-1`. Authoritative request: [classic-five REQUEST](../classic-five/REQUEST.md), sections 0–5, 8, 11–19. Implementation starts from `af2edf70cdf8fe46175f4fcf38fec607dda997d0` in isolated `/workspace/classic-author-023`. Only Game023 source, physical HTML, tests and records are authored here. Integration, catalog, Worker, publication and Sheet A31 verification belong to the root task.

Select one kana from a fixed full keyboard. Every matching position opens together; only new incorrect choices consume one of eight chances. Duplicate selections do nothing. All letters revealed is correct; the eighth miss ends the question and displays its answer. No timer, hangman imagery, score, BEST, ad or CREDIT. One question is one RUN. Next word starts the next RUN.

The independent keyboard offers the full 清音, 濁音・半濁音 and 小文字・長音 groups, including `ぢ・づ・ぱ・ゔ・っ・ゃ・ゅ・ょ・ー`; selection options never depend on the answer. Smartphone keys have five columns and at least 44 CSS pixels height. The 清音 group leaves gaps in the や/わ rows. Desktop supports native Tab/Enter/Space and arrows; used letters carry ○ or － as well as color and accessible labels. Repeats and clicks across a screen transition are guarded.

The initial 180 distinct readings are independently written in six categories, 30 per category. Each has an opaque `word_id`, NFC reading, category token, easy/normal difficulty and an original short clue. Readings have 3–8 characters and use only selectable keys. Clues appear with the answer after completion. No brands, works or named people are used. Original clue wording and code do not constitute legal clearance; name collision checks belong to integration.

The pure model uses a uint32 xorshift seed. It asks every remaining unseen word before cycling and retains the immediately previous question at the cycle boundary. Hints choose one hidden distinct letter deterministically, reveal all copies, spend no chance, and can finish the question. A second hint is ignored.

A single JSON record, `web-mini-arcade:v1:game023:question`, contains game/rules version, selection seed, recent cycle, question ID, guessed NFC kana, remaining chances, hint state, outcome, user selection count, run UUID, view state and a bounded reported ledger. Restore validates metadata and recomputes the exact outcome, including chronological terminal consistency. The same question and run UUID resume with no new run_start. A completed result restores without another report. Report flag and ledger share one write. Storage denial uses page memory; reload persistence cannot be promised in that case. No aggregate statistics are kept. Mute and practice completion use only Game023 StorageService keys.

Title offers immediate play, optional explanation and optional real two-word practice. Practice uses おにぎり and きゃべつ, teaching voiced and small kana through the same real controls. Both must be solved to complete practice. It does not modify production word history, result ledger, RUNs or statistics. Production suppresses practice events. Every overlay has a Portal link. Pause, visibility loss and blur stop input; pagehide saves without closing a RUN. Portal return preserves the question.

Existing StorageService, AudioService, TelemetryService, consent/environment and TouchGuard are reused. Game023 requests `remoteCollectionEnabled:false` while new-ID Worker registration is pending. Root owns the minimum shared `getActiveRunId()/restoreRun()` continuation boundary. Question telemetry is limited to word_id/category controlled tokens and numeric selection, wrong, remaining counts plus hint boolean and outcome. It sends neither the answer, free text nor kana history. Events are meaningful guesses/hints and save/restore lifecycle changes, never frames.

The visual brief is an original cream notebook with deep teal text, green paper details, eight quiet dots and roomy keys. No external image or sound assets are required.
