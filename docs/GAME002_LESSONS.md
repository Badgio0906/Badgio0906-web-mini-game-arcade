# Game002 — WORKDAY DODGE 実装からの発見

本ゲームの人間プレイテストは未実施。Game001 の人間評価 A〜J がすべて合格した事実を参考にするが、Game002 の面白さの証明には使わない。

## Game001 との差と面白さの核

ORBIT SHIFT は「切り替える時刻」が主技能だった。WORKDAY DODGE は、前方にいる相手と黄色い予告から「どのレーンが安全か」を先に判断する。入力は左右の 2 種類、場は 3 レーン。1000 m という明確な到着目標と、住宅街 → 商店街 → 駅周辺 → オフィス街の変化で進行を実感する。

歩行距離が唯一の主スコア。ギリギリ回避の NICE DODGE は小さな褒め演出で、追加ポイントへの変換はしない。安全に進むこと自体が目的になる。クリア後の延長モードは設けない。

## 判断したゲーム仕様

- 1 レーン移動は 130 ms の補間。移動中は次の 1 入力まで予約できる。2 回入力で 2 レーン移る場合も、各レーンを順に通る。
- 移動中も当たり判定がある。1/240 秒の小ステップに分け、プレイヤーと相手の移動範囲で接触を確認する。
- 最初の相手の中心到達は 9 秒、実際の接触開始は約 8.77 秒。開始してすぐの失敗を避け、操作を試す時間を作る。
- 1 波は直進 1 人、予告つき 1 レーン変更、まれな小さなフェイント、または 2 人組。3 レーン同時封鎖は生成しない。
- B は衝突時刻の 2.7 秒前から黄色い矢印と行き先の足元マーカーを出す。1.5 秒前に変更開始、1.26 秒前に完了する。C は 25 px の横振りをして元のレーンへ戻り、2.5 秒前から両方向の矢印で知らせる。
- 波の間隔は 3.1 秒から段階的に 2.25 秒まで短くなる。生成時には、接触区間、0.6 秒の判断時間、2 回のレーン移動を含む最低間隔を検証する。別パターンへの境界にも適用する。
- 歩行速度は距離に応じて 9 → 12 m/s。安全に進めた場合の 1000 m 到達は約 95.9 秒。進行が固定なので、クリア時間は記録情報であり速度操作の技能スコアではない。
- 失敗したフレームに CREDIT を 1 消費し保存する。結果パネルは 300 ms 後に表示するが、退出で消費を回避できない。
- RUN CLEAR は Game Over ではないため CREDIT を消費しない。開始時・生存中の退出も消費しない。この区別は今回の有限距離ゲームで初めて検証した。

## 再利用した部分

StorageService、CreditService、TelemetryService、Rewarded Ad Stub と AudioService の生成音機能を再利用した。保存先は `web-mini-arcade:v1:game002:` とし、Game001 の CREDIT、BEST、ミュート状態と混在させない。

AudioService の公開 `tone()` は、Game001 固有のイベント型を新ゲームへ押し付けずに使えた。音の鳴らし分けは本ゲームの UI モジュールに置いた。再利用を確認した後、既存の ORBIT 用の音対応も game 側へ移し、core のゲーム固有型への依存を除いた。

共通イベントは `game_id: game002` を自動付与する。終了理由 `over / clear / quit` と実時間、距離、自己ベストを同じ形で残し、固有イベントは `distance_reached / office_clear` に絞った。毎フレームの Analytics 記録はしない。

## ゲーム固有に保った部分

WorkdayRun は Phaser 非依存の 3 レーンモデル。敵の予告・移動、通勤距離、街の区間、到着判定を含む。WorkdayScene は Graphics で道路・建物・人物を描く。左右操作、予約入力、明るい通勤 UI、クリア結果は本ゲーム固有に置いた。

Game001 の 1 ボタン InputService は流用しない。1 レーンずつ進む 2 方向入力と、ボタンのネイティブ click / Enter を区別する必要があるため、AbortController で片付けられる小さな入力境界を作った。4 本以上で同じと確認される前に UI コンポーネント化しない。

## 実装・テスト上の発見

- 予告つき移動敵は、現在位置だけでなく「最終レーン」と「予告・変更時刻」をモデルに明示すると検証しやすい。
- 見える時刻と接触時刻を分けた固定予告時間により、後半でも急な敵出現を避けられる。
- 道路・人物は毎フレーム Graphics に描く。敵ごとの Phaser オブジェクトを生成しない。文字は固定 2 個と Graphics 1 個のみ。モデルの波と相手は通過後に削除する。
- Reduced motion 設定では画面 Shake、移動パルス、人物の歩行揺れを抑える。予告矢印など判断に必要な情報は残す。
- 診断 API は開発ビルドだけに置き、コピーした状態を返す。強制終了・時間加速・無敵を公開しない。ブラウザ確認では通常の左右入力を使う。
- 自動運転が回避できることは公平性の必要条件にすぎない。予告の見やすさ、スマートフォンの人物サイズ、瞬時に安全路を判断できるかは実画面で別に確認する。

## 自動テスト・独立レビュー

初期モデル QA では 5 seed の通常ステップと安全な左右入力で 1000 m 到達を確認。A〜D の全種、130 ms 補間、2 レーンを飛び越えない予約、先読み時刻、生成境界の安全、終了通知の重複防止、保存名前空間の分離を確認した。

実画面 Game Feel Review、ブラウザ QA、指摘修正後の再テスト結果はレビュー完了後に追記する。人間の楽しさ・再プレイ欲求の結果は下記項目で別途記録する。

### 独立レビューで見つかった問題と修正

- 保存済み 0 CREDIT でタイトルを開いたときの Reward offer 記録漏れと、結果から Reward へ移ったときの二重記録を修正。実際に表示した一つのオファーにつき一度記録する。
- BFCache に保存される `pagehide.persisted` を終了扱いすると、再開できる RUN に `quit / run_end` が混入する。保存される離脱はポーズだけにし、通常の終了と分けた。
- 同時 2 本指タップで 2 方向の入力が入る問題を修正。PointerEvent の primary pointer だけを移動入力に使う。
- 固定歩行速度なのにクリア時間を「最速」と呼ぶ表現を「到達時間」に変更。時間の保存値がない・壊れている場合は 0.0 秒と表示せず省略する。
- 1280×720 の PC でゲーム下部が画面外に出る問題を修正。短いデスクトップ画面ではヘッダーと余白を縮め、ゲーム幅を画面高さから決める。スマホ横画面の既存レイアウトは維持した。
- スマホの結果画面に NEW BEST と保存済み CLEAR 記録があると、見出しや TITLE がゲーム領域からはみ出す問題を修正。結果の余白を縮め、再挑戦 / 補充と TITLE を 2:1 の横並びにした。両ボタンの高さは最低 44 px。距離・BEST・TIME・CREDIT・CLEAR 記録は保持した。

実装担当の実画面再確認では、1280×720 と 1024×768 でゲームと下の操作案内が画面に収まり、390×844 と 320×568 で NEW BEST・CLEAR 記録・0 CREDIT が同時にある結果カードもゲーム領域内に収まった。独立 QA と Game Feel の最終再確認結果は別途追記する。

### 修正後の独立再確認

Game Feel Reviewer は実際のブラウザで通常の左右入力を使い、約 96 ゲーム秒の 1000 m 到達まで確認した。予告・レーン判断・到着の流れを確認し、最終レイアウト修正後も PASS とした。楽しさ・リトライ欲求の人間評価は未確定のまま残す。

QA Reviewer はモデル・サービスを含む 32 unit test、TypeScript、静的ビルド、修正対象の browser ケースを再確認した。CREDIT と Reward、BEST と CLEAR の保存、通常入力によるクリア、BFCache の再開、複数指入力、保存値の欠損、短い PC とスマホ結果画面の収まりを確認した。プロダクション経路の最終確認は QA 記録を参照する。

最終ゲート：Game Feel・QA・production 経路確認がすべて PASS。Game003 開始可となった。Game002 の人間プレイテストは引き続き未実施。

## 今回の旅・バイク改修（2026-10-04）

これ以前の有限1000m通勤の記録は過去版。現在は1000mで進行を完全停止し、出社CLEARと旅への続行を選ぶ。2000mで無料の得点確定終了、徒歩継続、200%バイクを選ぶ。旅に追加ゴールはなく、距離・NICE段階倍率のスコアは上限を設けない。旧距離BEST/出社時刻は保持し、SCORE BESTは別に保存する。

選択後は未処理の道路区間を切り替え、既得点・位置・時計・乱数列を保持したまま次の予告を十分先へ置く。バイクの世界・横移動・距離だけ2倍にし、実プレイのrun_durationを2倍にしない。safe_exitのBest確定と、未確定quitを区別する。

独立 [Feel](ten-game/reviews/GAME002_EXPANSION_FEEL.md) はPASS、[Visual](ten-game/reviews/GAME002_EXPANSION_VISUAL.md)は86/100、[QA](ten-game/QA/GAME002_QA.md)は13実ケースPASS。モデル25件の対象確認と全体77件の回帰を重複計上しない。実ブラウザはreadonly経路plannerの通常キー/タップで実行し、人間の面白さや実機性能を証明しない。
