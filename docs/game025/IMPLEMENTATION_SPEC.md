# Game025 · こつこつマインスイーパー ～MINESWEEPER～

Candidate No.71 / rules_version 1 / presentation_version prototype-1. Classic Minesweeper: 9×9 with10 mines or16×16 with40 mines. Open every safe cell to win; opening a mine loses. Flags are provisional marks and do not establish victory. All counts use true eight-neighbor adjacency. Zero expansion skips flags. Optional chording opens unflagged neighbors when surrounding flag count equals the number, and wrong flags can lose. Mines become fixed after initialization and never move during play.

First click and every valid neighboring cell are safe. Beginner creates independent own LCG candidates, then verifies with a solver accepting only public revealed numbers, dimensions and total mine count. Equations, zero/full constraints, subset differences and total mine count yield safe/mine deductions. Only proven safe cells can be chosen for solver opening. Reveal uses the answer to supply the number at the already selected cell. Ambiguous or unfinished boards are not verified. Generator version `public-subset-v1`.

Worker runs at most80 beginner attempts /450ms,12 intermediate attempts /300ms. Main host expires after1s and terminates the worker. Job IDs and state/pending-start guards discard stale results. Beginner has81 own previously verified fallback boards, each tied to its exact start coordinate with generation version and reproducible deduction steps. No translations. The initializer replays proof and requires proof.start===actual start. Intermediate uses the same verification when it succeeds; otherwise labels only first-click safety. No hidden changes rescue a stuck game.

Reasoned hints use the same public deduction boundary. User flags never enter the equations. A proven-safe flagged cell can be identified as a flag mistake, without auto-changing it. When no proof is available the UI says so and offers no answer peek. There is no runtime solver bot.

Cream background, teal typography, soft blue covered cells, pale open cells, amber flags and distinct mine/wrong-flag symbols. Code-drawn CSS only, system fonts, quiet synthesized audio; no copied product art or gray beveled Microsoft layout. All1–8 counts appear normally. Every beginner/intermediate cell is44×44 CSSpx on all viewports. The scoped #board .cell pan-x pan-y rule overrides shared TouchGuard touch-action:none by specificity; board/viewport ancestors are not marked as interaction targets. Smaller viewports horizontally pan both board sizes rather than shrinking the controls.

Mouse: left open, right flag. Touch: explicit open/flag selector. Arrows rove focus; Space/Enter open andF toggles flag. No longpress action. A hold longer than550ms, a move beyond9px or pointercancel cannot open a cell. Keyboard repeat cannot act. Focused opened number plus “周囲を開く” is optional chord. Pause/Escape/blur/background stop gameplay and elapsed active time; generation waiting also stops the clock. Hiding/blurring during generation retains pause intent; when verification finishes, the prepared board remains paused with its first click deferred until a manual Resume. Returning to visibility never auto-resumes. The saved firstOpenPending coordinate must exactly equal the verified start and is validated with a prepared, unopened board; pagehide preserves it. Consent settings remain reachable through the existing shared interface; game menus are nonmodal with inert board guards.

Title offers play/help/practice from the first visit. Practice is an actual independent beginner model and teaches place/remove a flag, then open. No production RUN, result statistics or game save is updated by practice. Start before practice abandons the prior real RUN explicitly. Practice completion is only recorded after the actual flag-and-open interaction.

One optional LocalStorage JSON snapshot (required save_version2) includes a game-local per-run resultId, game_id/rules_version, dimensions through difficulty, mines/counts/opened/flags/outcome/start/proof/history, active elapsed time, hints, original analytics UUIDv4 and result report ledger/statistics. Reads validate exact counts and replay every action, compare resulting flags/opened/outcome, replay beginner proof and reject start mismatches or incompatible versions. Game-local resultId is generated once per real run and used only for the result ledger; it is never an Analytics/browser ID, never sent in events and never passed to restoreRun. Result counts/report marker and terminal board are atomically written regardless of observer-ID availability; no new win/RUN on load. Active restore is an explicit title option and resumes into a paused menu. Existing TelemetryService creates the original run ID; restoration only calls restoreRun with that ID. Pagehide saves and emits no run_end. Audio/mute use StorageService + AudioService; existing TelemetryService installs TouchGuard. Save denial permanently selects page-local memory for this SaveStore instance, avoiding rereads of a valid stale backend snapshot; it does not establish reload persistence.

Meaningful telemetry only: difficulty, guarantee, opened count, flag count and operation count, hint count, outcome and elapsed seconds. No mines, board arrays or cell positions are sent. Consent/environment/upload remain the existing shared boundaries. This page explicitly sets remoteCollectionEnabled:false while parent Worker registration is blocked. CREDIT remains off. Parent integration owns catalog, build input, analytics registration, thumbnail and publication.
