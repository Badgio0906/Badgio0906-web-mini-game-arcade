# Game005 SORT SHIFT — Game Feel Review

担当: Game Feel Reviewer（Gameplay／UI／QA とは別担当）
結論: **実行に基づく Game Feel Review は PASS**。追加の実装修正を要する所見はない。人間の判断速度・楽しさ・再プレイ意向は未評価。

## 方法と限界

実際の Chromium で Arrow／A-D キー、ネイティブ LEFT／RIGHT ボタンへのマウス・Enter・Space、スマホの画面半分への座標タッチを使用。1366×900、390×844、844×390、320×568 で実行した。

高 SORTED の確認は、読み取り専用 `inspection().expectedSide` を参照して通常入力を送る **oracle 自動プレイ**。時間／スコア／荷物を書き換えず、終了は誤った方向への入力または自然な時間切れで発生させた。65 個の成功や短い所要時間を、人間の認知能力・平均 RUN 時間・楽しさの証拠にしない。

## 実行観察

| 観点 | 実行結果／判断 |
| --- | --- |
| 最初の 10 秒 | 最初から現在の SHAPE と左右条件、一つの荷物、残り時間を同じ盤面に表示。初期制限 4.8 秒、開始後約 1.43 秒で何も押さず残り約 3.37 秒。入力後は仕分け数が増え、短い搬出を挟んで次の荷物が来る。無入力の初回はゲーム時間 4.8 秒で TIME UP。これは放置時の終了時間で、初見の平均成績ではない。 |
| 操作 | Arrow／A-D の正解入力が受理される。独立したネイティブボタン確認で、マウス → フォーカスした Enter → Space がそれぞれ 1、2、3 SORTED に進めた。スマホでは LEFT／RIGHT の盤面半分をタップして実際に搬出できた。 |
| 見分け | 荷物の丸／角ばった外形、明／暗の塗りと LIGHT／DARK 表記、実際の小／大サイズ、中央の ○／× が同時に存在。現在の属性だけを説明する補助文字が下にあり、プレイ中の正解方向は表示されない。円形の荷物に ×、角形に ○ があるため、外形と記号が別属性と分かる。 |
| 遊びの違い | 明るい仕分け台、コンベア、一個ずつの分類と明示されたルール変更。Game002 の先を読んだ通勤回避、Game004 の順序記憶とは異なる、現在の条件を選び直す操作になっている。人間が認知の切替を楽しめるかは別途確認する。 |
| 搬出のテンポ | 正解時に SORTED／COMBO と反応が更新され、荷物が左右へ搬出。短い NEXT PARCEL 表示は透明な小ラベルで、出ていく荷物を覆わない。最初の正解直後に ArrowLeft／ArrowRight／A を続けて送っても SORTED 1 のまま。搬出中の入力を次の荷物へ持ち越さない。 |
| ルール変更 | 8 個ごとに SHAPE → LIGHT → SIZE → SYMBOL。32 個から同じ 4 属性の左右反転を実際に確認。黄色の RULE CHANGE と「左右反転！」、REVERSE を含む見出し、変更後の左右条件が先に出る。古い荷物が残らず、表示時間約 0.95 秒は判定入力と荷物の制限時間が停止。変更中の実キー・タッチは仕分け数を増やさない。 |
| Pause | RULE CHANGE の途中で Pause。650ms 待ってもゲーム時間差 0、変更の残り時間 0.83 秒を保持。Resume 後に同じ新条件の表示の続きを経て次の荷物へ進んだ。 |
| 難易度上限 | 通常キーによる oracle 自動プレイで 65 SORTED／65 COMBO、ゲーム時間 26.421 秒、全 8 通りの属性／反転に到達。終盤の decisionSeconds 1.3 秒を確認。人間の経験者 RUN 時間ではない。 |
| スコア | 正しく仕分けた個数 SORTED が主表示、COMBO と BEST が補助。失敗した荷物を加算しない。65 個で間違えた結果が SORTED 65／BEST 65／COMBO 65、リロード後も BEST 65 と残り CREDIT 1 を保持。 |
| 誤方向の失敗 | 「そっちじゃなかった！」と、実際に選んだ左／右を表示。盤面に荷物と現在のルールを残し、正解の入力ボタンを黄色で強調。正解方向と属性の説明を盤面と結果カードの両方に表示する。反転後の誤入力でもその時の条件に対応する。 |
| 時間切れの失敗 | 新 RUN の荷物を放置し、自然に 4.8 秒で「時間切れ！」「仕分けの時間がなくなりました。」へ。誤方向を選んだという表示にならず、正解方向は同様に確認できた。 |
| Retry | 結果の短い誤操作防止期間後、通常クリックから新しい SORTED 0 の確認まで約 56ms。古い訂正表示が新 RUN に残らない。 |
| スマホの高個数 | 縦・横で実タッチによる oracle 自動プレイ 33 個、4 属性と SHAPE の反転まで到達して通常の誤入力で終了。320×568 では 9 個と LIGHT への変更を確認。方向の判定をプログラム呼出しで代替していない。 |
| UI と CREDIT | 縦・横・小画面とも NEW BEST、失敗理由、正解方向、CREDIT、補充／TITLE が画面内。入力と結果のボタン最小高さ 44px。保存済み 1 CREDIT を用意し、通常の誤入力で 0 に到達して、開発版 Stub を押し 3 に戻った。これは状態準備であり、各端末で 3 回自然終了したという主張ではない。 |

## 修正後の独立確認

UI 担当が 320×568 の Reward／Pending カード下端が画面を超える所見を報告。親の修正ウィンドウ指示で Feel の実行を止め、補充／TITLE の横並びへの変更後にスマホの実タッチレビューを最初から実施した。変更前に完了したデスクトップのゲームループ確認は、変更対象が Reward のマークアップだけのため保持した。

| 画面 | 結果カード下端 | Pending カード下端 | Pause カード下端 | 画面高さ |
| --- | ---: | ---: | ---: | ---: |
| 390×844 | 754.09px | 717.58px | 667.98px | 844px |
| 844×390 | 356.50px | 335.47px | 315.92px | 390px |
| 320×568 | 559.09px | 543.48px | 510.44px | 568px |

小画面でも Pending の補充ボタン、無効化された TITLE、開発版 Stub の説明が見える。補充後に CREDIT 3 のタイトルへ戻る。結果の荷物／訂正とカードが重なって読めなくなる所見はない。

## 人間で判断すること

現在属性の補助文字は分類を助けるが、左右条件との照合はプレイヤーが行う。補助文字が適切な支援か、切替の面白さを弱めるかは人間プレイで判断する。32 個以降の反転の負荷、1.3 秒の下限、初見の 4.8 秒、実機での文字の読みやすさについて自動成功を根拠に調整不要と断定しない。音は実装イベントとの動作を確認したが、気持ちよさを人間が聴いて評価したものではない。
