# Game003 DROP TOWER — Game Feel Review

担当: Game Feel Reviewer（実装担当／QA とは別担当）
結論: **実行に基づく Game Feel Review は PASS**。Game004 に進める。人間の面白さ・初心者 RUN 時間・再プレイ意向は未評価。

## 方法と限界

実際の Chromium で 1366×900、390×844、844×390 を確認し、通常の Space／Enter／タップ経路で荷物を落とした。診断 API は荷物位置・支持部・重心・状態の読み取りだけに使用。位置変更・強制終了・早送りを使っていない。

中心付近を狙うプレイ、偏った配置を積み重ねるプレイ、意図的な支持端外の DROP を分けて確認した。自動操作で測った成績は人間の成績ではない。実機の 60fps、音の聞き心地、気持ちよさ、「もう 1 個」の欲求は人間で確認する。

## 観察

| 観点 | 実行結果／判断 |
| --- | --- |
| 最初の 10 秒 | プレイ開始直後から荷物が揺れ、Space で離せる。最初の DROP はゲーム時間 0.117 秒、1.217 秒に 1 FLOORS／0.7m／PERFECT +100。次の荷物を約 7 秒待っても勝手に落ちず、落とす時刻を自分で選べる。自動で迫る Game001/002 と違う静かな判断時間がある。 |
| 操作案内 | Space / Enter / Click / Tap、DROP ボタンが見える。吊り下げ中は「DROP READY」、落下中・着地待ちは別の短い文とボタン無効で状況を伝える。 |
| 連打 | 最初の荷物を落とした直後に Space／Space／Enter を入力しても同じ荷物の落下が続く。次に生成された荷物は吊り下げ状態で待ち、過去の入力で自動 DROP されなかった。タップ連打でも同じ。 |
| テンポ | 離す→目に見える落下→接触→短い着地待ち→次の吊り下げ。落とした瞬間に数値だけ増える構成ではなく、落下と着地を見る時間がある。急ぐ操作を強制しない。 |
| 本物の積み上げ | 箱は元の幅を保持し、重なった部分だけに切り詰められない。幅・高さ・kg 表示が異なる荷物を確認。ずれた荷物を積むと重心と支持部の関係が変わり、上の荷物だけの失敗と下の接点の崩壊が別に発生した。 |
| 初期の余裕 | 最初の 3 荷物は広く、揺れが小さい。中心付近で 3 回着地し、その後の多少ずれた非 PERFECT の着地も継続した。1 個の小さい揺れや PERFECT を外しただけで即終了することは観察していない。 |
| 主スコアの判断 | **実際に積めた個数 FLOORS を主表示として採用する。** 箱の高さの違いがあっても 1 箱＝1 FLOORS で理解できる。高さ m は補助表示。PERFECT／BONUS は別欄で、+100 が架空の 100 階に変換されない。 |
| PERFECT | 最初の 3 連続 PERFECT は 1／2／3 FLOORS、累計 BONUS 100／300／600 と別に伸びた。黄金色の短いポップアップを確認。人間がタイミングを気持ちよく狙えるか、音程上昇が心地よいかは未確定。 |
| 長めのプレイ | 中心付近を狙う実入力で 14 FLOORS／9.58m、ゲーム時間 77.446 秒、PERFECT 5、MAX COMBO 3、BONUS 800。その後 15 個目を意図的に支持端の外へ落とした。 |
| 上の荷物の失敗 | 15 個目は実際の端を支点に傾いてから横へ落下。既に積んだ 14 箱は保持し、最終値 14 FLOORS。結果は「荷物が塔の横へ落ちました。」。失敗した荷物を成功階数として数えない。 |
| 下の支持部の崩壊 | 別 RUN で左右に偏らせた 5 FLOORS／3.4m の塔を作った。5 個目の着地後、18.918 秒で BALANCE の危険表示、上部の「重心に注意」、下側の弱い接点（index 1）に支持線／重心マーカーを確認。次の荷重で 20.447 秒に崩壊。結果は「重心が支えの外へ。塔が崩れました。」で、荷物単体の落下と区別される。 |
| 失敗の予告 | 偏った塔の見た目と BALANCE バーの上昇が連動する。実際に弱い下の接点にも印があり、常に塔の頂点だけを危険箇所として表示していない。すべての高層・乱数配置で十分読みやすいという証明ではなく、人間の E 項目で確認する。 |
| カメラ | 6／10／14 階の画面を確認。塔が高くなると視点が上がり、地面が見えなくなっても左の m 目盛りと HUD の高さが増す。天井のクレーンと次の荷物・塔の上部は画面内に残る。 |
| Retry／保存 | 結果画面から Retry で吊り下げ状態に戻り、ロード画面なし。並行ヘッドレス負荷下のクリックから再開確認まで約 1.70 秒。リロード後に BEST 14 を確認。 |
| CREDIT／Stub | 縦・横で残り 1 CREDIT を保存したテスト状態から、通常のタップで 3 階を積み、その次を端へ落として 0 CREDIT に到達。+3 CREDIT を押すと 3 に補充しタイトルへ戻る。保存値は UI 状態の準備用であり、3 回自然死亡したという主張ではない。 |
| 縦・横 UI | 縦では結果カード 310×355.6px が 362×434.4px のゲーム枠内に収まる。横は塔の隣に 300×222.5px の結果カードを配置し、すべて画面内。SCORE／BEST／HEIGHT／PERFECT／BONUS／CREDIT、補充と TITLE が見える。 |
| 視覚方向 | 鋼材のクレーン、木製箱、リベット、kg、建築の目盛りで工業・建築の世界観がある。Game002 の人物と街の絵を色替えしたものではない。 |

## 留保／次の判断

明白な Game Feel の修正必須問題は、この実行では発見していない。下の接点がカメラ外になる長い塔での危険の理解、最初の 3 個から次の広い揺れへの体感、Perfect の狙いやすさは人間で確認する。

14 階の実行は並行ヘッドレス描画負荷下で約 197.6 実秒を要した。モデルは長いフレームを抑制するため、仮想環境の実時間とゲーム時間は一致しない。この実行を一般スマホの fps や初心者の平均 RUN 時間として扱わない。
