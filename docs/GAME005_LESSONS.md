# GAME005_LESSONS — SORT SHIFT

## Game004 との差と核

静かな記憶グリッドから、明るい物流カウンターで現在の判定軸を切り替えるゲームへ変えた。主スコアは正しく仕分けた荷物数。COMBO は同じ連続正解数で、別の水増しスコアにしない。荷物の形・明るさ・大きさ・記号は独立に生成し、現在のルールだけで左右を決める。外側のカードではなく中央の物体そのものを丸／角として描く。明るさには LIGHT ☀ / DARK ▧ の文字・模様による手掛かりも付ける。

最初の 8 個は形、次の 8 個は明るさ、続いて大きさ、記号。その後 32 個目から 4 軸の左右を反転し、64 個で通常方向へ戻る。変更時には新しい対応を 0.95 秒表示し、荷物・入力・判断締切を止める。旧荷物を新しいルールで判定しない。通常の仕分け中には正解方向を表示せず、ルールと荷物の属性だけを表示する。

判断時間は最初 4.8 秒で、正解 1 個ごとに 0.06 秒短縮、下限 1.3 秒。正解後の発送は 0.23 秒で NEXT PARCEL を表示し、連打を受け付けない。新しい荷物が現れた時点で、その荷物の締切が始まる。誤答・時間切れは即時に 1 回だけ終了し、期待方向、実際の方向または未入力、該当属性、ルールを記録する。発送とルール変更を含むプレイ中の時間を記録し、pause 中は全て止める。

## 構造と再利用

Gameplay Engineer が純粋な SortRun、DOM の SortBoard、contracts、metadata を担当し、UI Engineer が HTML・main・CSS を担当した。Main は方針・統合・追加レビューを担当し、QA と Game Feel Reviewer は独立して確認する。

Storage、CREDIT、Rewarded Stub、音、Telemetry だけを既存 core から使い、UI は独自にした。Phaser はこのゲームの依存グラフに含めず、ネイティブ DOM と CSS で荷物の到着・発送・仕分け台を描く。モデルは RNG を注入でき、ブラウザ・広告・保存先を知らない。inspection と result はコピーを返す。開発時の読み取り専用 diagnostics は main が公開し、強制終了・時間加速・状態変更 API は作らない。

## 実装しづらかった部分・入力

仕分け台の左右タップは primary pointerdown で即時に扱う。内部の native LEFT / RIGHT ボタンはこの経路から除外し、クリックを二重計上しない。ボタンの click.isPrimary は Chromium では primary マウスでも false になるため使わず、primary pointerdown の pointerId と荷物 ID を照合する。WATCH で持ち越したタップを防いだ Game004 の知見を荷物単位に適用した。

Enter / Space も押し始めた荷物 ID を保持し、別の入力で次の荷物へ進んだ後にキーを離しても旧操作を注入しない。矢印 / A / D は repeat と修飾キーを除外する。dialog・pause・title の操作をゲーム入力にしない。destroy は RAF、DOM、AbortController による全入力 listener を解除する。

## テスト・レビュー

最終の独立 QA は PASS。Game005 model QA 6 件と既存 47 件、計 53 件の unit が成功した。開発版の実ブラウザは重複を除いた 10 実行が成功し、11 件は他 project との意図的な重複として skip。TypeScript check と静的 build、production の Game005 1 実行も成功した。実際にロードされた JavaScript は Game005 17,993 bytes と共通 service 4,135 bytes の計 22,128 bytes で、Phaser・開発用 diagnostics・canvas が含まれないことを確認した。自動正解 planner は状態遷移と表示を検証する道具で、人間の判断負荷・楽しさ・想定プレイ時間を証明しない。

Game Feel Reviewer は通常キーと読み取り専用 diagnostics を使い、65 個の仕分け、4 軸それぞれの通常・反転の計 8 対応、下限 1.3 秒の締切まで確認した。記録は 26.421 秒のゲーム内時間で、ルール切替中の pause、発送中の連打拒否、56 ms のリトライ反応、無入力での 4.8 秒の時間切れも確認した。これは高速な自動正解方針の記録であり、初心者・経験者の人間の所要時間ではない。

修正後の独立 Feel は PASS。390 px portrait と 844 px landscape は通常の半画面タップでそれぞれ 33 個まで進み、4 軸の通常対応と反転 SHAPE を確認した。320 px は 9 個まで進み LIGHT への切替を確認。各画面で保存済み 1 CREDIT → 通常の誤答 → CREDIT 0 → Stub 補充で 3 CREDIT を確認し、結果・pause・補充中表示と 44 px 以上の操作面も確認した。マウス、native Enter、native Space で 1 → 2 → 3 個と一度ずつ仕分けできた。詳細は [GAME005_FEEL](reviews/GAME005_FEEL.md) と [GAME005_QA](reviews/GAME005_QA.md)。両レビューの最終 gate を通過した。人間 A〜J、特に理解・リトライ意欲・CREDIT 補充を選びたくなるかは未実施のまま残す。

QA の reload 保存確認では、テスト側が毎回 CREDIT 1 を上書きしていたため、保存済み 0 を誤って変更していた。fixture は保存値がない場合だけ初期値を置くように修正し、実装を変えずに再検証した。保存テストの失敗では、アプリと test harness のどちらが状態を書いたかを切り分ける。

## レビューで直した表示

発送中の NEXT PARCEL を最初は不透明な全面 banner で表示しており、正しく仕分けた荷物が左右へ出ていく動きを覆っていた。発送時は小さな透明 badge に変更し、全面表示は rule_change のみにした。入力拒否の意図を示しながら、0.23 秒の発送自体を見せる。

320 × 568 の NEW BEST・CREDIT 0 の結果でカードが画面外へ伸びた。コンパクトな結果レイアウトに直し、正解方向、BEST、CREDIT、補充と TITLE を残した。通常の結果だけでなく、新記録と CREDIT 0 が同時に出る状態を検証する必要がある。

同じ 320 × 568 で Rewarded Stub の補充中カードの下端が 598.48 px まで伸びた。補充と TITLE を横に並べる配置へ変え、下端を 543.48 px に収めた。操作面は各 44 px 以上を維持し、補充中は TITLE と brand の遷移をロックする。結果の画面サイズ確認だけでは、補充中にボタン文言が変わる状態の高さまでは保証できなかった。

45 / 100 秒は初心者／経験者の設計目標で、実測した人間の達成時間ではない。0 個の無入力 run は 4.8 秒で終わり、正解を重ねるほど判断締切が短くなる。人間によるプレイテストは未実施。

## 共通化候補・共通化すべきでないもの

保存 namespace、run 終了時の即時 CREDIT 消費、reward 表示機会の一度だけの計測、pause と page lifecycle、dev-only diagnostics、入力 epoch の考え方は複数ゲームで確認できた候補。Game004 の sequence、Game005 のルール周期、荷物描画、左右入力、発送時計はゲーム固有であり、無理に共通 scene にしない。

今後は native ゲームの共通 UI を切り出す前に、result の位置、主要ボタンサイズ、可視状態からの reward 計測が複数のゲームで本当に一致するかを比較する。難度の人間評価後に判断秒数や反転の告知を調整し、広告回数からゲームの良し悪しを決めない。

## 今回のルール大型化・日本語/英語改修（2026-10-04）

現在は日本語を既定とし、丸い/角ばっている、明るい/暗い、小さい/大きいと左右の対応を大きな実UIで表示する。プレイ中も見える日本語/ENボタンで切り替え、英語ではルール・説明・練習・結果・HUD・サイドの説明を訳す。日本語主題＋英題はどちらでも保持する。

言語はゲーム005固有namespaceのboolean `english`で保存。分類IDや締切に使わず、Boardの表示signatureとUI文面だけを更新する。練習の正解済み段階、本編、結果表示の保護タイマーを再起動しない。SortRunとcontractsは今回の保護監査でバイト一致を要求する。

16属性組合せ×8ルール×2言語の正しい分類と文面の一致を含む3件の純粋localeテストが成功。実操作と画面サイズは[今回のQA台帳](ten-game/QA/README.md)で結果を確認する。人間A–Jは今回も未実施。新しい分岐は追加していないためK–Mは進行先/難度の上達について適用できる範囲を記録し、Nは読みやすさとゲーム内の軽い笑いを確認する。
