# Game004 — ECHO GRID 実装からの発見

Game004 の人間プレイテストは未実施。以下の期待時間や再プレイ要因は設計仮説であり、実測による評価ではない。

## Game001〜003 との差と面白さの核

操作の速さや物理配置から、短期記憶と集中に主技能を移した。光る順番を見て、同じ順番を 9 個のパネルで再現する。次の LEVEL を覚え切りたいという欲求を、主スコアの到達 LEVEL と副スコアの正解入力数で表す。

## 判断した仕様

- LEVEL 1 は 2 個。新しい LEVEL ごとに新しい sequence を提示し、長さは最大 9 個までに制限する。無制限に長くして人間の記憶量を超える方向へは進めない。
- 最初の表示は 0.6 秒点灯と 0.18 秒消灯。後半も最低 0.28 秒点灯・0.12 秒消灯。連続して同じパネルが出る場合も、必ず一度消えてから点灯する。
- 初期 3 LEVEL は同じパネルの連続を避ける。LEVEL 4 以降で連続を許すが、3 回以上の同一連続は生成しない。
- 見ている WATCH 中の入力は無視する。RECALL 中は人工的な遅延や入力間隔制限を加えず、入力を即座に判定する。
- 思い出すための制限時間を設けない。時間切れによる反射神経ゲームに変えない。
- 1 回の誤入力で即座に RUN 終了、CREDIT と BEST の保存を先に行う。間違えたパネルと次の正解を示し、その後に正しい sequence を 0.18 秒点灯・0.12 秒消灯で再表示する。
- 正解の再表示は結果画面から見える。リトライは 300 ms 後に可能とし、長い sequence の再表示完了を強制的に待たせない。新しい RUN や TITLE で古い再表示をキャンセルする。
- 主スコアは到達した LEVEL。LEVEL 1 で失敗した場合も LEVEL 1 到達として記録する。正解入力の総数は別の指標として保存・表示する。

## 技術と再利用の境界

このゲームは TypeScript + Vite とネイティブ DOM の 9 個の button で実装した。Phaser を必要としないため、このページの依存グラフにはゲームエンジンを含めない。軽量 Web 技術を許容する元の技術方針に従い、セル入力、フォーカス、Enter / Space のアクセシビリティを自然に使うことを優先した。

再利用は保存、CREDIT、Reward、生成音、Telemetry。保存先は `web-mini-arcade:v1:game004:`。基本イベントの形式は他ゲームと揃え、`memory_level / sequence_length` を追加する。Game001〜003 のゲームロジックや Phaser Scene、結果 Overlay は流用しない。

EchoRun は純粋な TypeScript の WATCH / RECALL / BETWEEN / ENDED と生成・判定を担当。EchoBoard は実際の 9 ボタン、RAF と見える信号、入力、失敗後の再表示を担当。Main の UI 層はライフサイクル・開始・結果・CREDIT を担当する。Gameplay Engineer はモデルと Board、Main Agent は方針・統合・追加レビュー、UI Engineer はネイティブ HTML と電子パネルの CSS、QA と Game Feel は独立レビューを担当した。

## 実装上の発見

- 同じマスの連続は、点灯だけでなく消灯区間もモデル化する必要がある。
- 「入力できない WATCH」と「入力する RECALL」を明示すれば、早押しを失敗扱いにせずに済む。
- disabled button でも点灯・番号は十分なコントラストを維持する。共通の disabled opacity を適用すると、難しさが記憶から視認性へずれてしまう。
- 押した瞬間に終わる判定と、失敗後の説明演出は別の時計で動かす。CREDIT を演出の終わりまで待って消費しない。
- ネイティブ click を主入力とし、修飾キーや第 2 の pointer、キーの長押しを別入力として混入させない。1〜9 の番号キーは任意の補助操作。Main の Space をプレイ中の汎用入力にはしない。
- DOM の class / aria-pressed は見える状態が変わった時だけ更新する。RAF ごとに同じ属性を書き直す必要はない。
- 描画オブジェクトは 9 ボタンで固定。破棄時には RAF と AbortController のリスナーをまとめて止める。

## レビュー・テスト

独立 QA のモデル、実ブラウザ入力、保存、pause、WATCH の消灯区間、結果と再表示、レスポンシブ、production の結果は終了後に追記する。

Game Feel は実画面を使って、ルール理解・点灯の分かりやすさ・失敗理由・再挑戦を確認する。自動テストが sequence を読み取って正解できることは、ユーザーの記憶体験や面白さの証明にはしない。

初期ブラウザ確認で、Chromium の正常なマウス操作でも `pointerdown.isPrimary = true` の後の `click.isPrimary` は false と判明した。click の値だけで拒否する実装を修正し、RECALL 中の primary pointerdown で承認した pointerId・セル・LEVEL と click を対応させた。WATCH の押しっぱなし、別 LEVEL まで持ち越す操作、2 本目の指を誤入力として混入させない。ネイティブボタンの Enter / Space はそのまま受け付ける。

### 修正後の独立レビュー

技術ゲートは PASS。全プロジェクトの 47 unit test、Game004 の 12 件の distinct dev browser ケース、1 件の production 確認、TypeScript と静的 build が成功した。通常のマウス・タッチ・Enter / Space、WATCH からの押しっぱなし、修飾キー、複数指、pause、終了時の CREDIT、Reward、BEST と reload、結果と再表示を確認した。読み込んだ JavaScript 合計は 19,866 bytes で、Game004 では Phaser を読み込まない。

Game Feel Reviewer は desktop で LEVEL 16、mobile で LEVEL 8 まで通常のセル入力で確認し、同じパネルの反復、結果と正解再表示の同時表示、0 CREDIT と Stub、320 px の画面、一時停止を確認して PASS とした。高 LEVEL の成功確認は読み取り診断から sequence を得た自動入力を含むため、人間が記憶して楽しめる証明とはしない。人間 A〜J の結果は引き続き未実施。

## 共通仕様候補と固有部分

終了時の CREDIT、Reward と保存障害回復、生成音、Telemetry、可視性と BFCache のポーズは再利用できた。入力方式、画面内の役割、結果の置き場所はジャンルの目的で変える必要があった。

記憶 sequence、点灯 / 消灯、WATCH 中の入力抑制、誤入力の説明、到達 LEVEL の意味は固有に残す。結果 Overlay でゲーム面を覆う UI を全ジャンル共通にすると、今回の正解再表示を隠してしまう。
