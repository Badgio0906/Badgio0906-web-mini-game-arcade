## Findings and disposition

1. **Fixed: production local history could backfill pre-consent actions.** Initial browser fixture observed no keys/network before consent, but first post-grant action persisted `page_ready`, `run_start`, and a prior fall as well as the new action. External upload was already future-only. Main agent added a production consent-change history reset that preserves previously consented historical records while discarding the current pre-consent memory backlog. Final fixture stores and uploads only the post-grant action. Existing bounded device-local history intentionally survives withdrawal; withdrawal stops new persistent records and removes external IDs/queue, as the user's instruction requires.
2. **Fixed: grant → revoke before GA load → regrant lost required initialization.** Clearing the pending dataLayer removed js/config but the previous `loaded` early return prevented restoring them. Final adapter restores configuration on each grant and appends the vendor script only once. A blocked-vendor fixture checks restored config, clean page_view, no calls after withdrawal, and one script.
3. **Fixed: GA lacked a portal/late-grant page_view.** `send_page_view:false` previously depended on game_open, which excluded the portal and was intentionally not replayed after consent. Adapter now emits a fresh consented current-page view; game_open no longer duplicates it.
4. **Fixed: initial clean GA page_view omitted campaign attribution.** Removing raw URL query correctly prevented leakage but also removed UTM before acquisition measurement. Adapter now obtains sanitized current/retained-visit attribution and supplies campaign fields and hostname-only referrer on initial config/page_view. The fixture verifies tiktok/launch and `https://x.com/`, with no query in page_location.

No unresolved blocking issue found within this client review's tested scope. This is not a claim of live Google collection, deployed Worker/D1 persistence, or physical-phone testing.

## Boundaries

The legacy adapter instruments the shell and marks its events `legacy-shell-only`; native engine RUNs are not invented. A missing page_exit is not an inferred abandonment. GA configuration is disabled without a measurement ID; external upload is disabled without endpoint configuration. The inspected client never calls Jev or awaits upload in gameplay handlers. Existing BEST/CREDIT/game physics are outside this review and covered by the main task's regression checks.

This independent review used Chromium in a local Vite browser. Real iPhone long-press/callout, live GA Realtime, production Worker/D1, HTTPS delivery and compiled all-game regression are separately required or explicitly left unverified by their owners. Cancellation cannot retract an already delivered POST, and withdrawal is not retroactive server deletion.

An earlier `client-review-initial.json` was overwritten by an intermediate development run that imported two HMR runtime instances and therefore yielded no post-grant events; it is not acceptance evidence. Final lifecycle fixture accesses the TelemetryService-owned runtime, avoiding the module-copy problem. Preliminary fixture assertion failures were collector issues (hidden panel after Space activated its focused consent button; duplicate HMR module imports), and final assertions were corrected without changing product code for those failures.
