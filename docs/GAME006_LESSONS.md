## 遊びと既存ゲームとの差

自由運転ではなく二段階の一入力ゲーム。ANGLE で前輪の操舵角を固定し、POWER で走行距離を固定する。車体をその場で回す操作ではない。固定された曲率と距離で車が前進し、最後の向き・位置が決まる。Game003 の落下時刻や Game002 の車線移動とは異なる空間判断を狙う。

角度は −38〜38 度、Power は 0〜1。曲率は `tan(angle)/110`、距離は `120 + 220*power`。定曲率の円弧を厳密に積分する。描画もモデルが返した円弧を使い、演出用の別軌道は使わない。ANGLE では最大到達距離までの薄い曲線、POWER では現在値での予測終点と車体四角を中立色で表示する。正解判定や理想入力値をプレイ中に表示しない。

駐車には車体四隅のすべてが区画の内側に入る必要がある。隣の車との接触は回転矩形の SAT と swept hull で確認する。走行を最大 0.5px / 0.25 度の小区間に分け、車体と中心軌道の円弧 sagitta を含む余白で swept hull を補う。接触図形の交差から接触点を表示する。枠外の理由は実際の角度・枠座標上の横ずれ・進み不足・行き過ぎから決定する。

## 配置・難易度・禁断の選択

有限の7テンプレート。最初2台は直進、続いて25度の斜め、40度の斜め、7台以降は左右90度の縦列枠も候補になる。各区画は実現可能な円弧の終点から作り、左右の駐車車両を置く。生成時にその円弧が全区間で安全かを検証する。車種は見た目のみで、全車42×70の同じ物理矩形を使う。

通常区画は72×106から徐々に狭まり、56×90を下限とする。隣の車は区画中央から左右71pxに置く。角度ゲージ周期は24秒から18秒を下限、Power周期は9秒から7秒を下限とする。判断の締切は設けない。走行は約1.22〜1.45秒、成功固定は0.65秒。実時間は入力待ち・走行・成功固定を含み、ポーズと選択中は停止する。

10台成功後、一度だけ次の50×82の狭い枠を実際の図で提示する。「やめておく」は通常枠へ戻し、「入る」はその RUN の残りを禁断駐車にする。選択中は時計・ゲージ・走行が停止する。新たな入力なしに車が発進することはない。車両の外観や運動条件は変えず、枠だけ狭める。

GOOD=100、GREAT=150、PERFECT PARK=200。完全に枠内に収まった成功の位置・角度誤差を区画余裕に対して正規化し、0.2以下PERFECT、0.55以下GREAT、それ以外GOODとする。PERFECT連続で倍率1、1.25、1.5、1.75、2へ増え、最大2。他の成功は連続をリセットする。禁断モードは今後獲得する点だけ2倍。過去の点を遡って増やさない。主記録はスコア、成功台数・PERFECT数・最大連続は別に残す。

## 素材と画面

Art Director が実際に確認した ImageGen 車3種を採用。朱色コンパクト、紺セダン、ミントバン。配信画像合計52,134bytes。実際のalpha>8境界を確認した：compact `[4,3,188,318]`、sedan `[10,3,181,318]`、van `[5,2,186,318]`、各192×320。全画像を物理矩形42×70内へ描くため、ミラーを含め見かけが当たり判定を越えない。

## 検証と難しかった点

最終ゲージ変更を含む `npm run check` と `npm run build` 成功。独立 QA モデル7/7成功（3.98秒）。全7テンプレート通常/禁断を実際のゲージ待ちで実現し、強さ不足/行き過ぎ/角度違い、中心円弧と極薄障害物の接触、10台停止と将来点のみ2倍、60台の保持数・深いコピーを確認した。設計した7テンプレートを通常/禁断・各難易度でモデル生成し、安全検証成功。表示図形から角度と距離を計算する入力オラクルの試走で、5種類のテンプレート選択条件それぞれ禁断モード35台まで到達した。最短95.3秒、最長158.8秒。これは変更前の速すぎるゲージによるモデルと入力到達性の証明であり、人間の判断速度・面白さの証拠ではない。Rootレビューで実際の枠内判定からタイミング許容幅を測り、ゲージを遅くした。初回区画は操舵角5.115度・距離36.01pxの成功幅があり、新しい曲線で約514ms・470msの窓となる。通常最小枠は角度約175ms以上・Power約181ms以上、禁断枠は角度約100ms・Power約108ms（もう一方を中心値に置いた場合）。二つの誤差が重なると窓は狭まる。改訂後の通常入力オラクル5条件は、初回成功9.71秒、10台選択83.6〜105.7秒、通常20台145.3〜236.7秒へ到達した。メタデータの経験者目安190秒はこの検証からの設計参考値で、初心者60秒も設計仮説であり、人間の初回失敗時間は未測定。数値の目標値とオラクルの到達時間を別フィールドに記録する。SINの角度振幅も38度へ減らした。各ANGLEは枠に依存しない−38度から開始し、最初の直進の中央通過は6秒。必要最大操舵角32.62度を保ちつつ、最初の空間判断を急がせない。

特に難しい点は、曲線走行の小区間で中心軌道も曲がること、回転矩形の枠内判定、90度縦列の車両配置、二段階入力をブラウザのキー保持やclick二重経路が短絡しないこと。Root reviewで swept hull 余白に中心円弧の sagitta が抜けていた点を修正した。QA は極薄の障害物、回転接触、全テンプレート、10台の停止と選択、精度倍率、破棄・保存・自然失敗を検証する。実ブラウザのScene/UI、モバイル操作、見た目の独立評価は次工程。

独立Feelの実ブラウザで、3台目の斜め枠へほぼ正しい操舵角を固定した後、POWERを約0.00265で発進して手前に止まったのに「角度が合わず」と表示する問題を検出した。曲線は走行距離不足だけでも終端角度が変わるため、終端角度だけで原因を操舵へ帰属させてはいけない。全ブラウザを閉じた修正windowで、実際の軌道・当たり判定・精度・得点を保ったまま理由だけを修正した。見えている開始点/枠の角度/直線距離から必要な円弧距離を算出し、現在の操舵ならその距離で完全に枠へ入る場合は、選んだ距離の不足/過剰を説明する。複合的な大きな進行方向のずれは「強さと角度を確認」、横/姿勢主体のずれは角度として説明する。独立QAは左右の斜め枠で操舵±0.573度・最低POWERの通常入力を再現し、正しく不足表示/過去450点保持を確認した。既存7件を保って最終8/8件成功（テスト2.794秒/runner3.10秒）。修正後の実ブラウザ・残る画面サイズ確認は再検証待ちで、まだ最終ブラウザ合格ではない。
