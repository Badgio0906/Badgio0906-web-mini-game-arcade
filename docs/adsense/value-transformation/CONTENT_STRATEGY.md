# 100ガレのコンテンツ戦略

2026-10-31 JST。基準origin/main `6211019f`。実装・現在の検証結果は[実装報告](IMPLEMENTATION_REPORT.md)、作品の根拠は[監査](GAME_VALUE_AUDIT.md)。

## 価値提案と対象

ブラウザで無料ですぐ遊べる、異なる操作・判断を持つゲームセンター。オリジナルの仕組みを持つ作品と、定番のルールを100ガレで遊べる作品を、違いが分かる案内で発見できることを価値とする。全作品が独創的な新ジャンル、全作品が短時間で終わる、と誇張しない。5分の釣行、時間制限のないパズル、終了まで一定でないシミュレーションが共存する。

初回訪問者には「何を操作するか」「何を目指すか」「いつ終わるか」「他の作品との違い」。再訪者には直接PLAY、お気に入り、個人の記録、別の遊び方への比較を提供する。人気や再訪率の実測値は今回取得していないため、おすすめ順位を捏造しない。

## 情報設計

```text
トップ＝ゲーム一覧（既存PLAY・タグ・お気に入り・記録）
 ├ 初めての方へ・ゲームの選び方（guide.html）
 │  ├ 一入力／時間制限なし／物理／記録から比較
 │  ├ 初回FAQ
 │  └ 全公開作品の遊び方一覧
 ├ 各カードの遊び方・コツ（guides/gameNNN.html）
 │  ├ 実画面・目的・PC/スマホ操作・判断・終了と記録
 │  ├ このゲームを遊ぶ → 既存の起動URL
 │  └ 違いの分かる関連2作品のガイド
 └ about（問い合わせ含む）／privacy（既存）
```

ゲーム画面は固定高さ、初回modal、Godot shell、回転停止などに依存する。本文をプレイ画面へ追加する案と、同じタイトルの説明ページを設ける案を比較し、今回は後者を選ぶ。物理・入力・保存境界を触らず、ゲームから一覧へ戻って説明を探す既存経路も保つ。直接PLAYに中間ページを強制しない。新たなゲーム内ヘッダーやmodalを挿入しない。

28ページは28個の異なる公開作品に1つずつ対応する詳細であり、検索語ごとのバリエーションページではない。生成は手動編集した原稿の整形のみ。各ページの主要な目的は操作と判断への回答で、全作品一律の宣伝文は置かない。比較ページからは実際のプレイURLも直接選べる。

## 編集ルール

1. `src/content/gameGuides.ts` が本文の編集元。名前・URL・公開状態は既存catalogを参照し、二重管理しない。非公開・削除作品を案内に混ぜない。
2. 各原稿のevidenceと監査に根拠を残す。manifestは手がかりで、実装と食い違えば実挙動を調べる。旧版や候補実装を公開版の説明へ流用しない。
3. PCとスマホの操作、向き、終了と記録を必要十分に書く。023にBESTを作らず、038のゲーム内人数を現実の統計にしないなど、作品の差を保つ。
4. 判断のコツは、どの状況で何を比べるかを書く。「コツは練習」「誰でも簡単」「必勝」だけでは採用しない。最適攻略と実測成功率を推測しない。
5. 制作体験・面白さ・人間の感想・所要時間の実測は実際の確認がある場合だけ。コード読み、モデル、ブラウザ通常入力、人間評価を監査で区別する。
6. 実ゲーム画面の既存サムネイルを使い、架空の豪華な画面を作らない。本文はシステム日本語フォントで表示し、既存subsetを書き換えない。
7. 共通レイアウトは共有するが、固有の見出しと判断を編集する。将来セクション数を増減できるschemaとし、文字数を必須条件にしない。
8. 変更時は `npm run guides:build`、`npm run guides:check`、対象のリンク・実操作を確認。通常build前にも原稿と出力の同期を検査する。

## 受入と継続改善

今回の受入：全公開作品に根拠のある説明、一覧から説明と実プレイへ到達、root/Pagesサブパスでのリンク、JSなしの本文、狭幅での読みやすさ、公開・保存・計測・広告境界の保持。記事数・文字数を改善成果として採点しない。

次に人間へ確かめること：初見で1作品を選び目的を言えるか、説明だけで最初の操作を理解できるか、012/013横・015縦の違いを理解できるか、次に遊びたい作品が見つかるか。特に013の実機4領域と音の同期は未完。完成状態は作者判断を維持する。

将来の分析は既存の同意済み集計だけを使う。今回イベントを新設しないため「ガイドの効果で再訪が改善」とは測定できない。必要なら別設計で、プライバシーと既存契約を守った計測範囲を決める。
