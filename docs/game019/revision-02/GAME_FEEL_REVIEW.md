# Game019 改訂02 — 独立Game Feelレビュー

**ジャンプ／地形／失敗の技術・設計gate PASS。人間の面白さは未評価。** 実装者とは別のworkerが、研究・Before分析・20m試作の合格後に、固定した本番候補をPC／phone／320px／短横画面で実操作した。保存統計に見つかった整数／小数の不整合も、019限定修正・実StorageService単体・compiled4画面の実保存／再読込証拠により解消した。変更は保存helperとその呼出だけで、物理・入力・map・表示・素材のhashは不変。 [QA_REPORT](QA_REPORT.md) に発見と限定再検証を記録した。

本家のマップ・アート・経路を参考データとして使っていない。独自手作りmapをread-only forecastで観察し、通常キー／native CDP touchでチャージと離す操作を行った。位置・時間・model stateを注入せず、DEV診断から跳躍関数を直接呼んでいない。これは技術・代理評価であり、初見の人間が解けたという結果ではない。

## 核の成立

旧版Beforeでは小0／中1／大31回で200mへ進んだ。新候補の実観測では、PC59跳躍＝短5／中38／長16、phone66＝短7／中51／長8、320px54＝短3／中40／長11、短横54＝短3／中43／長8。これは故意の失敗と再登りを含むQA controllerのRUNで、一般ユーザーの利用割合や難度を推定する値ではない。それでも中が主力、小が位置合わせ、長が段差／近道という役割が実操作で存在する。

押すだけでは跳ばず、最大700msまで溜めても離すまで待つ。短押しで出発点を動かし、左・真上・右をrelease前に決定する。練習5では発射後に逆方向を押し、150ms後も水平速度が同じだった。空中で救える方式へ戻っていない。カエルの3姿勢の本番hold画像も、発射しないままpause取消して確認した。POWER数値／正解軌道を本番に出していない。

## 各場所が違う判断を要求する

- 低い梁を避ける中チャージ、13.9mの木棚での短い準備→根への長跳躍、22.8mの狭い石、25.2mの受け棚とひび石、苔の横滑り、50mの広い棚、57.2mへの大きな段差、動くバケツ、70mの分岐、出口の光を通常入力で辿った。
- 70mの分岐は、危険側70→77.5→82.2mの2跳躍と、安全側70→72.4→75.2→78.1→82.2mの4跳躍。実RUN全体の時間差は故意の落下も含むので比較しない。幅・経路・受け棚を選べることを評価する。
- 旧版の中心／最大反復と同じ攻略になっていない。新authored levelの独立public-API replayで最大700msだけを左右／真上へ分岐する有限探索は112試行／38状態、20m着地0、最高頂点19.2m。3px状態丸めと12跳躍上限があるので数学的な全経路否定ではない。20m試作での通常最大真上8回の停滞も別に保存済み。

## 失敗の差と再登り

同じRUNで、損失0の同棚着地、3.7mの戻り、4.2mのcatch、13.9mの底への戻り、77.5→50mの27.5m戻りを実行した。上空155→100mの55m戻りも検証中の不足チャージから実際に起きた。後者ではRUNも生存し、100mの実棚に着地した。進行を失い、飛び方を変えて登ることが罰であり、Game Over／復活teleportではない。

27.5m戻り後に同じRUNで再び77.5mを越えた。catch使用eventと同一run_idも記録した。全失敗が同じ戻り距離にはならず、高い棚への近道が失敗した時の結果も見える。50mの棚は実物で、セーブ復帰を行わない。章2の100m岸も再登り可能な実地形であり、そこで詰んだのはcontrollerの経路索引不足だった。

通常の上寄りcameraで次の足場を見せ、下を見る操作と右端のcatch断面図で戻り先を示す。人間が小さい断面図を初見で読めるか、危険側の下を十分に認知できるかは未検証。技術的に描かれていることと、理解／緊張の評価を混同しない。

## 井戸から空へ

全4viewportで100mの海・鳥、章2、200mの宇宙／CLEARへ通常入力で到達した。暗い井戸の水／根／木／苔／光から海へ、鳥の移動で空へ進む展開が実装され、操作は同じチャージ＋方向のまま。章2では左右／上昇／下降と弱・中・強の風を踏み切りeventで全て確認した。風は手作り高度帯で予告され、踏み切り時の風が着地まで続く。途中の時刻乱数で風向きを変えていない。

「海に出て嬉しい」「え、まだ続くの？」「宇宙まで行きたい」という感情は、人間評価がないのでPASSとしない。構造と表示が成立したという判定に留める。

## 証拠と残す限界

[集約とsource hashes](QA/final-independent/SUMMARY.json)、[20m関門](PROTOTYPE_FEEL_REVIEW.md)、[最終QA](QA_REPORT.md)。PC／phone／320／短横の画像と本番charge3姿勢は `QA/final-independent/` と `controlled-fall-rerun/`、`final-desktop/`。

collectorのFAILを合格に書き換えていない。各失敗原本から、実施された到達／落下／入力のcaseを合算して判定した。横画面title導線の実不足はrootのCSS修正後の全RUNで確認。深い落下の狭い100ms窓、不足チャージ後のshore索引、未選択のdeep候補は検証基盤の前提不足として分類し、同じsourceの別RUNに既存のcase証拠がある。無目的に全RUNを追加反復しない。

全browser contexts／browserは終了済み。実機の音量、音楽の好み、親指、FPS、酔い、初見のチャージ認知、悔しさ、もう一度遊びたい感覚は未実施。独立Visualは別workerが判定する。
