# Game019 改訂02：手作りの井戸と空

研究、現行実プレイ分析、独立20m prototype gateの後に制作した固定地形。対象は019のみ。Jump Kingの足場座標・背景・アートは使用していない。

正本は `src/games/game019/authoredLevel.ts` の `createAuthoredLevel()`。360 logical px、24px/m、55足場。井戸30足場＋100m海岸＋上空24足場、井戸12／空12の記憶用セクション。生成seedやRNGはない。ジャンプ後の入力補正もない。

## 地形の意図

| 高度 | 記憶する場所 | 判断 |
|---|---|---|
| 0–8m | 水面の石 | 広い石で中チャージと左右を学ぶ |
| 8–15m | 低い木の梁 | 大チャージが常に正解にはならない |
| 15–23m | 遠い根の石 | 小ジャンプで踏切位置を変え、長く溜める |
| 23–31m | 割れたレンガ | 細い石、25.2m受け棚、ひび石 |
| 31–40m | 苔の壁 | 少し滑る着地を見越す |
| 40–46m | 古い板の折り返し | 短い段差と方向転換 |
| 46–50.1m | 半分の休み棚 | 1.1m小段、50mの幅280px物理catch |
| 50.1–60m | 根の大きな切れ目 | 7.2m大段差。長チャージが必要 |
| 60–70m | 古いバケツ | 唯一の動く足場、18px振幅、4.4秒周期 |
| 70–80m | 二つの帰り道 | 右の安全棚か、左の77.5m短い危険ルート |
| 80–90m | 光る苔とひび石 | 既習の溜め分けと着地位置 |
| 90–100m | 井戸の出口 | 明るい出口へ最後の左右跳躍 |

独立試作の最初の6足場と12.7mの梁は全く同じ座標・幅・材質を継承した。25.2／50／75.2mは保存checkpointではなく地形。50mの棚は壁際の落下も受け止める幅、25／75mは片側を外すと下へ落ちる。すべての失敗が井戸底まで戻る設計にはしない。

70mの分岐は同じ入口・同じ82.2m合流点を共有する。安全側は72.4→75.2→78.1mの3着地、危険側は左77.5mの狭い1着地で2ジャンプ短縮。危険側の外側ミスは75m棚を通り抜け、50mに受け止められて27.5m戻る。視認用のcamera／見下ろし／地形図は描画側の責任で、plannerの予測線は本番に出さない。

## 空はジャンプの発展

100mに達すると海→鳥の演出を経て104mの `sky-start` へ運ばれる。これは章演出であり、落下時の自動復帰には使わない。200mの星に実際に着地してCLEAR。

| 高度 | 場所 | 踏切の固定風 |
|---|---|---|
| 104–112 | 鳥の置き土産 | 左・弱 |
| 112–120 | 右向きの旗 | 右・中 |
| 120–128 | 湧き上がる雲 | 上・中 |
| 128–136 | 左向きの旗 | 左・中 |
| 136–144 | 重たい空気 | 下・弱 |
| 144–152 | 雲の休み棚 | 右・弱 |
| 152–160 | 長い風の旗 | 右・強 |
| 160–168 | 鳥の通り道 | 左・強 |
| 168–176 | 持ち上がる氷晶 | 上・強 |
| 176–184 | 沈む氷晶 | 下・強 |
| 184–192 | 星の渡り道 | 左・弱 |
| 192–201 | 宇宙への一跳び | 上・弱 |

横加速20／38／65px/s²、上下補正60～160px/s²。風はジャンプ開始時に選択し、その飛行の着地まで固定する。高さの境界を横切っても空中で突然変化しない。上空も等間隔ではなく、4m前後の段・6m以上の上昇気流段・広い受け雲などを使い分ける。147／184mに物理catchを置く。ギミックの数ではなく、踏切時の方向とチャージの読み替えを中心にする。

## 実行したモデル検証

`node tests/game019/level-plan.mjs` はreadonly `forecast()` で候補を選び、`setDirection`→`beginCharge`→120Hz tick→`releaseCharge`→実際の着地を実行する。player位置の代入、既存RUNを途中から開始するfixture、ゴールへのテレポートは使っていない。完全経路と全イベントは [safe-path](QA/model-level/safe-path.json)、[risk-path](QA/model-level/risk-path.json)、追加確認は [model-study](QA/model-level/model-study.json)。固定charge／方向／着地IDをユニットに残した。

- 安全／危険両ルートで井戸底から200mの星まで到達。海・鳥・風全4方向と全3強度を通る。
- 唯一のbucketに初期clockを0／1.1／2.2／3.3秒変えて着地。静止足場へ置き換えていない。
- ミスの進行損失1.1／3.7／10.3／7.2／27.5mを実飛行で確認。落下後もaliveでチャージを開始できる。
- 最大700msだけで全3方向を試すdepth20探索は38離散状態で閉じ、最高着地10.2m。これは2px／4vx丸めを使う技術的探索で、数学的全入力証明とは区別する。最大直上12回も梁の下7.2mで止まる。
- 両経路の各着地姿勢から次の実入力が存在する。海岸は演出用地形、最終星は終了地点。任意の端ぎりぎり姿勢からの無失敗復帰を証明したものではない。
- nominal入力の各ジャンプに±20msを与える単発forecastも保存。累積誤差を含む全RUN保証ではない。実際のPC／mobileは別のnative browser QAで確認する。

## 局所調整と失敗記録

初期版の50→57.2m棚は幅64pxで、600msが頂点近くの一点狙いとなり、±20msの2入力が失敗した。この結果を `initial-narrow-*` に保持。段差7.2mは維持し、棚の中心を266→282px、幅64→108pxへ広げた。600～700msに着地窓ができ、長すぎる場合は壁に当たって同じ棚へ着地する。短すぎる時は50mへ戻る。

幅の変更後、旧200ms左入力では同じ広い棚に戻るため、50m落下のテストfixtureが1件失敗した。製品バグではなく変更前の着地仮定を残した基盤不一致。`post-widen-fixture-failure.log` と `post-widen-invalid-catch-sample.json` を保持し、300ms左の実落下に変更、損失とcatch IDをassertして再検証した。初回sampleのPASS表示だけを最終根拠に使わない。

これはモデル到達性・入力精度・学習可能な固定地形の技術検証。人間がジャンプ自体を楽しいと感じるか、実機の親指操作／音／長時間の落下ストレスは未実施。独立Feel／Visual／browser QAと人間試遊を別判定として扱う。
