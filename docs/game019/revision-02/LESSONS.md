# Game019 改訂02 — 実装からの学び

- Jump Kingの公式説明・guide・評価を調べ、charge-releaseの決断と固定地形の学習を採用した。キャラクター・map・固有表現はコピーしない。
- 旧版はすでに空中修正0だった。退屈さの原因を『空中修正がある』と決めつけず、実操作で大31／中1／小0と最大真上91.2mを確認した。
- 平地→20m→独立gateの順で進めた。20mで小の準備、中の主力、大のリスク、0／3.7／10.3m進行損失が成立してから100m／空を制作した。
- 手作りmapでは1.1〜7.2mの主経路段差、狭い石、梁、moving bucket、safe／shortcut、catchを組み合わせた。全大一択の拒否を有限探索と通常入力で区別して検証した。
- 50mの7.2m段差は最初の狭い棚で±20msに弱かった。段差は保ち幅と位置だけ調整し、106/106試行の単発±20ms toleranceを確認。これは連続した人間成功率の測定ではない。
- 50m棚を大きくしたことで上部の普通の失敗が毎回底へ戻るのを防いだ。一方、25/75mの棚は横を外すと通過する物理地形にして、万能checkpointにはしない。
- 風は足場の固定帯から読んで踏み切り時に固定する。境界を空中で跨いでも急に変わらない。風の弱中強を乱数の嫌がらせに使わない。
- QAの72forecast getterをチャージ中にpollすると入力時間を伸ばした。cheap snapshotとexpensive forecastを別getterへ分け、実入力のhold→release後にeventのchargeを確認する。
- 間違ったcatchの予測、失敗後にxが初期化される思い込み、float厳密比較はharnessの問題として原本を残す。製品の修正や合格数へ転用しない。
- 3段の溜め姿勢は画像の縦圧縮でなく整数pixelで別描きした。日本語の新21字は019限定fontへ追加し、他18ゲームのfontを変えない。
- モデル到達、入力QA、独立Visual、公開、実機の人間評価を別に記録する。人間の『もう一回』は未実施。
