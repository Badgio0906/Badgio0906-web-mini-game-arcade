Game002〜005 改修指示書
タイトル表示・UI改善・個別ゲーム追加仕様
0. このタスクの目的
既存の Game002〜Game005 について、
良かったビジュアルの方向性は活かしつつ、以下の問題を修正すること。
今回の主な修正目的
1. 英題のみだと分かりにくいので、邦題＋英題併記にする
2. PC版のゲーム表示領域が小さすぎるので、より大きく見やすくする
3. フォントが固く、雰囲気がやや無機質なので、もう少しポップで親しみやすい方向へ統一する
4. 各ゲームに個別の追加要素・スコア要素・演出を加える
5. SORT SHIFT はルールが分かりにくいため、プレイ前の説明導線を入れる
1. 最重要方針
今回の修正では、以下を守ること。
維持したいもの
- 各ゲームの基本コンセプト
- 既存のゲーム性の核
- CREDIT仕様
- 基本操作
- 既存の良いビジュアル方向
変更してよいもの
- タイトル表示
- フォント
- レイアウト
- UIサイズ
- HUD見せ方
- プレイ前導線
- スコア表示
- リザルト表示
- 称号やコメント演出
- 一部追加スコア要素
- チュートリアル表示
- Game Over画面の演出文言
注意
単にテキストを足すだけではなく、
「遊ぶ前に理解しやすく、遊んだ後に少し笑える・印象に残る」 方向で整えること。
2. 全ゲーム共通修正
2-1. タイトルは邦題＋英題併記にする
今後は英題のみではなく、邦題を主、英題を副として併記する。
基本形式：
邦題 ～ENGLISH TITLE～

もしくは
邦題
ENGLISH TITLE

どちらでもよいが、プレイヤーが最初に日本語タイトルを認識できることを優先する。
英題は完全に消さない。
シリーズ感・海外感・ゲーム一覧での識別のため残す。
2-2. PC版のゲーム表示領域を大きくする
現状、PCブラウザ上でゲーム画面がやや小さい。
添付のスクリーンショットでも、余白が大きく、プレイ領域が相対的に小さい印象がある。
対応方針：
- PC版では、ゲームの実表示領域をより大きく取る
- 「雰囲気重視の余白」は残してよいが、プレイ領域の小ささがストレスにならないことを優先
- 特に Gameplay中の視認性 を優先
- タイトル画面 / プレイ画面 / リザルト画面 すべてについて見直す
- 1920×1080 近辺の一般的PC表示で、小さすぎると感じないサイズにする
ただし、単純に全要素を拡大して崩すのではなく、
余白設計を見直して、中心のゲーム体験が主役になるようにすること。
2-3. フォントを見直す
現状のフォントは「固い・真面目・雰囲気はあるがやや堅苦しい」。
今後は、
統一フォントでもよいが、もう少しポップで親しみやすい方向 にする。
要件：
- 可読性が高い
- 日本語表示がきれい
- 少し遊び心がある
- ただし安っぽくしない
- ゲームごとの雰囲気を損なわない
- 英字・数字・日本語が併記されても破綻しない
方針としては、
- 見出し用フォント
- 本文/UI用フォント
を分けてもよい。
ただし複雑すぎないこと。
全ゲームを通して同じデザイン言語を感じる 状態が望ましい。
2-4. リザルト画面に「遊び」が欲しい
各ゲームの Game Over / Result 画面は、
単なるスコア表示だけでなく、少し笑える・印象に残るコメントや称号を追加する。
ただし、テンポを損なわないよう、
一目で分かる短い文言 を基本とする。
3. Game002 改修指示
邦題：
ゆううつな月曜日 ～WORKDAY DODGE～
3-1. タイトル
以下を正式タイトルとする。
ゆううつな月曜日 ～WORKDAY DODGE～

ゲーム一覧・タイトル画面・リザルト画面など、必要に応じて表示。
3-2. 追加スコア要素：「ナイスドッジ」
WORKDAY DODGE に、
直前回避（ナイスドッジ） の要素を加える。
要件
- プレイヤーがぶつかりおじさん等を かなりギリギリで回避した場合、NICE DODGE と判定
- NICE DODGE の回数をカウント
- Game Over 時に、到達距離をベースにスコアを計算する
スコア計算ルール
「距離 × ナイスドッジ回数」ではない。
ナイスドッジ回数に応じて、
距離に段階的ボーナス倍率をかける方式 にする。
例（あくまで叩き台。最終調整可）：
- 0〜2回：ボーナスなし（100%）
- 3〜5回：110%
- 6〜9回：125%
- 10〜14回：145%
- 15回以上：170%
最終スコア：
最終スコア = 到達距離 × ボーナス倍率

表示
Result画面では最低限、
- 到達距離
- NICE DODGE回数
- ボーナス倍率
- 最終スコア
を表示する。
例：
距離：648 m
NICE DODGE：8回
ボーナス：125%
SCORE：810

数値の見せ方はゲームに合うよう調整してよい。
3-3. 直前回避の演出
NICE DODGE 成立時は、短く気持ちいい演出を入れる。
例：
- NICE DODGE!
- 軽いSE
- 小さなフラッシュ
- コンボ風の連続感（必要なら）
ただし、プレイの視認性は損なわないこと。
4. Game003 改修指示
邦題：
我が国の建築は世界一ぃ！ ～DROP TOWER～
4-1. タイトル
正式タイトル：
我が国の建築は世界一ぃ！ ～DROP TOWER～

少し大げさでバカっぽい熱量を出してよい。
DROP TOWER の英題は残す。
4-2. 称号システムを追加する
積んだ高さ・階数・スコアなどに応じて、
リザルト時に称号 を与える。
基本方針
- 低スコア帯は比較的普通の称号
- 高スコア帯になるほど、だんだんおかしな形容詞が増える
- ある臨界点を超えたら、小さい子供がふざけて考えたような、やたら盛られた称号 にする
- プレイヤーが「次の変な称号を見たい」と思えるようにする
例
低め：
- 三流大工
- 見習い大工
- 町の職人
- 一流棟梁
中〜高め：
- 伝説の棟梁
- 超一流建築王
- 鉄骨マスター
- 積みの求道者
かなり高い：
- 超スーパーエグゼクティブウルトラ神大工
- 銀河最強積み積み大棟梁
- ハイパーミラクル天空建築覇王
- スーパーアルティメット無敵積層親方
※文言は最終的にCodex側で複数案作って調整してよい。
ただし方向性は 「後半ほどふざける」 で統一すること。
4-3. リザルト表示
最低限以下を表示：
- 積んだ階数 or 高さ
- スコア
- 獲得称号
例：
高さ：32.4m
階数：18 FLOORS
称号：一流棟梁

または高スコア時：
称号：超スーパーエグゼクティブウルトラ神大工

称号は目立たせる。
ただし長文になりすぎる場合は表示崩れに注意。
5. Game004 改修指示
邦題：
あなたの短期記憶、無事ですか？ ～ECHO GRID～
5-1. タイトル
正式タイトル：
あなたの短期記憶、無事ですか？ ～ECHO GRID～

少し煽る感じ・軽いユーモアがあるタイトルにする。
5-2. リザルトに「記憶力年齢コメント」を追加する
スコアや到達レベルに応じて、
「○○歳相当の記憶力です（わが家の子供調べ）」 のようなコメントを表示する。
方針
- 厳密な医学的・科学的評価にはしない
- あくまでネタ・ゲーム内ジョーク
- 表現は軽く、笑える感じにする
- 不快にならないよう、あまり露骨に下げすぎない
- スコアが低くても「ちょっといじられる」程度にする
例
低スコア：
- 5歳相当の記憶力です（わが家の子供調べ）
- うちの甥っ子といい勝負です（わが家の子供調べ）
中スコア：
- 16歳相当の記憶力です（わが家の子供調べ）
- まだまだ現役です（わが家の子供調べ）
高スコア：
- 28歳相当の記憶力です（わが家の子供調べ）
- かなり冴えています（わが家の子供調べ）
超高スコア：
- 人類上位クラスの記憶力かもしれません（わが家の子供調べ）
- もはや記憶装置です（わが家の子供調べ）
実装方針
スコア帯に応じて階段状にコメントを切り替える。
5-3. リザルト表示
最低限以下を表示：
- 到達レベル
- ベスト
- 記憶力コメント
必要なら、
- 成功入力数
- シーケンス長
なども追加可。
6. Game005 改修指示
邦題：
右往左往の仕分け術 ～SORT SHIFT～
6-1. タイトル
正式タイトル：
右往左往の仕分け術 ～SORT SHIFT～

理由：
- 左右仕分けのゲーム性が伝わる
- 混乱と判断のゲームであることが伝わる
- 少しシャレ感がある
- 邦題として覚えやすい
6-2. 最重要課題：ルールが分からない問題を解消する
現状、SORT SHIFT は ルールが非常に分かりにくい。
これは最優先で改善する。
必須対応
ゲーム開始前に、簡単で明快なルール説明を挟む。
6-3. プレイ前説明の仕様
以下のような、1画面または短い2段階の説明導線を用意する。
必須内容
1. 何をするゲームか
2. 左/右に何を振り分けるか
3. ルールは途中で変わること
4. ミスすると終了すること
5. PC/スマホの操作方法
6-4. おすすめ構成
画面1：概要
例：
流れてくるモノを、
今のルールに従って
左か右に仕分けよう！

まちがえると終了。
ルールは途中で変わるぞ！

画面2：具体例
例：
たとえば…

ROUND → 左
ANGULAR → 右

丸いものは左、
角ばったものは右！

[練習してみる]
[本番へ]

さらに望ましい仕様
可能なら、1〜2個だけ実際に触る練習ステップ を挟む。
例：
- 丸い物体が1つ来る
- 左へ送る
- 正解！
- 次に角ばった物体
- 右へ送る
- これでOK、本番へ
この練習は短く、テンポを損なわないこと。
6-5. ルール変更の見せ方
本編中の RULE CHANGE も、
もう少し分かりやすくしてよい。
例えば：
- 切替前に短く停止
- 新ルールを大きく表示
- 左右の対応を視覚的に示す
- 0.8〜1.2秒程度しっかり見せる
プレイヤーが
「何が変わったのか分からない」
状態にならないようにする。
6-6. リザルト
最低限、
- 正解数
- ベスト
- 到達ルール段階やコンボ（必要なら）
を表示。
必要なら軽いコメントも加えてよい。
7. タイトル表示のデザイン方針
全ゲームに共通して、タイトルは以下のように整理する。
方針
- 邦題を主タイトル
- 英題を副題
- 英題は小さめでよい
- 一覧でも判別しやすいこと
- タイトル画面・Result画面で世界観を壊さないこと
例
ゆううつな月曜日
WORKDAY DODGE

または
ゆううつな月曜日 ～WORKDAY DODGE～

ゲームごとに最適な見せ方を選んでよい。
ただし「日本語を最初に認識できること」を優先する。
8. フォント改善の具体方針
以下の方向で再選定する。
要件
- 日本語見出しが映える
- 遊び心がある
- UI数字も読みやすい
- 少しポップ
- ただし子供向けに寄りすぎない
- 4ゲームすべてに適用可能な統一感がある
推奨
- 見出し系：少し個性あり
- UI本文：視認性重視
- 数字：読みやすいもの
必要ならフォントを複数組み合わせる。
ただしバラバラな印象にならないようにする。
9. PC版レイアウト改善
添付スクリーンショットのように、
PC版では余白が広く、ゲーム部分がやや小さい印象がある。
改善指示
- プレイ領域を拡大
- 特にゲームキャンバスの見やすさを上げる
- タイトル・説明・UI・HUD・余白の比率を見直す
- 画面全体がスカスカに見えないようにする
- ただし「ただ拡大しただけ」の雑な対応にはしない
- Desktop での没入感を優先
モバイル
モバイル版は破綻しないこと。
PC版を大きくした結果、モバイルが崩れないよう注意。

- フォントがポップ寄りになりつつ読みやすいか

- Score表示が分かりやすいか

- 高スコア帯の称号が十分ふざけているか

Game004
