# Game032 — 固有モデルと再現条件

対象：`src/games/game032/FishingModel.ts`。DOM・Canvas・保存・音・Telemetry・共有から独立した純粋ルール。Game032の実装以外を変更しない。

## 操作／時間

`FishingModel({mode:'standard'|'practice',random?:()=>number})`。本番は前景で動いた300秒、練習は別モデルで無制限。`update(seconds,{left,right,reeling})`は1回0.25秒以下、1/120秒以下のsubstep。異常に長い差分は背景時間としてまとめて実行しない。描画側で非表示／メニュー時をpauseにし、再開frame時刻も更新する。

`startCharge()`→長押し→`releaseCast()`。最大1.25秒、0–0.34未満は近／0.34–0.74未満は中／0.74以上は遠。左右移動は待機中のみ、岸の連続座標0.08–0.92、速度0.23/秒。最寄りの4地点が釣り場所になる。

`hook()`は本アタリの1.6秒（練習2.3秒）内で成功。前アタリは0.8秒あり、早合わせ／遅合わせは失敗して1.6秒後に再キャスト可能。失敗はGameOverにしない。`cancelInput()`は未完了チャージと巻き入力を解除し、キャンセルをキャストに変換しない。`setPaused(true)`も同様で、経過時間・待機・ファイトを停止する。

キャスト飛行0.9秒、待機2.2–4.2秒（深みは＋1.5秒）。本番の適正距離の反応率は浅瀬94%、岩陰90%、木陰86%、深み82%。不適距離はそれぞれ0.63倍。練習は反応確定。

## 場所／魚

| 地点 | 適正距離 | 主な魚／特徴 |
|---|---|---|
| 浅瀬 | 近 | オイカワ・ウグイ、数を釣りやすい |
| 岩陰 | 中 | ヤマメ中心 |
| 木陰 | 近 | アマゴ・イワナ、希少魚寄り |
| 深み | 遠 | ニジマス・大きめのサイズ、川の主の相対比率が高い |

出現は定義済みの地点別weightによる抽選。適正距離を外すとニジマス・イワナ・主のweightを0.45倍にする。サイズ帯／強さ／点数は一元化した`FISH`に保持。6種と超低weightの川の主1種。RNGは注入可能で、同じ入力と乱数列を再現できる。

## ファイト／得点

引く→休むを交互に表示できる状態。引く時間は`1.1+強さ×0.25`秒、休む時間は1.9秒。初期テンション0.25。引く間に巻くと毎秒`0.47×強さ`上昇、放すと0.025上昇。休む間は巻けば0.09、放せば0.24下降。テンション1で糸切れ。練習は引く間の上昇を0.68倍。休む間の巻きで取り込み進行`0.34/強さ`/秒、引く間は`0.024/強さ`/秒。取り込み1で成功。放置のみでは24秒、主は32秒で逃げる。

得点は整数：魚種基本点＋サイズ帯内の相対サイズ×80四捨五入＋定義済み希少bonus＋上位20%サイズなら100＋連続成功bonus（2匹目5、以後5刻み、最大30）。失敗で連続成功数だけ0に戻し、既得点は失わない。取り込みの加算とeventは各1回。本番300秒到達後は保留中の魚を加点しない。

1匹の最大は1110点。飛行0.9＋最短待機2.2＋前アタリ0.8＝最低3.9秒/匹で、ファイトを無視した上限でも300秒で76匹・84360点。公開記録の保守的な許容上限は`SCORE_LIMIT=100000`。これは実測の上達期待値ではない。

## 描画／統合契約

`model.snapshot`はfreezeされたreadonlyスナップショット。フェーズ、経過／残り時間、座標／地点、チャージ、距離、テンション、取り込み、引きのON/OFFと残り秒、魚、最後の釣果、釣果一覧、整数得点、連続成功、失敗理由、pauseを返す。`drainEvents()`は離散eventを1回だけ返し、毎frameの外部イベントにしない。event queueは最大256。実装側が練習の外部送信／BEST／共有を除外する。

## モデル検証

`npx vitest run tests/unit/game032-model.test.ts`で地点差／距離差／7種定義、キャスト→前アタリ→本アタリ、早／遅合わせ、全押し糸切れ、休む時だけ巻く取り込み、放置逃げ、希少主、連続bonus、締切300秒、直前の魚非加点、練習分離、pause／cancel、異常dt、8seedの5分合成シミュレーション、再現性とreadonlyを確認。

初回の締切テストは`reach('fight',1)`でhookなし・1秒だけ進めていたためwaitingで失敗。テストの操作経路を本アタリ到達→hook→締切へ修正し、モデル変更なしで成功。これは自動fixtureの技術確認であり、ブラウザ実操作／人間の気持ちよさの評価ではない。
