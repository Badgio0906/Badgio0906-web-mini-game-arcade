# Game019 — チャージ式改修前の独立分析

対象は Game019「井の中の蛙、大海を目指す」だけ。2026-10-05 UTC に旧公開版のソースを dev server で実行した。実装者と別の Before 分析担当が通常キー／タップで遊び、読み取り専用 DEV forecast を判断補助に用いた。これは動作・到達性の技術確認であり、人間の楽しさや初見の習熟を計測した結果ではない。

基準 commit: `fcc4156a53988fc24aa70967534c5669e279fb38`、branch: `codex/game019-charge-redesign`。Game019 runtime／HTML と TelemetryService の SHA-256 は [実行 report](game019/revision-02/QA/before/report.json) に保存。実行中に runtime は変更していない。公開サーバーを直接操作した確認ではなく、この commit のローカル再現である。

## 単調さの主要仮説

もっとも強い実行根拠は、井戸の大部分が真上・大の同じ選択で進むこと。中心座標は左右に揺れていても、偶数段が中央の9mジャンプで届くため、見た目の蛇行が実際の判断になっていない。全体到達に小ジャンプが一度も必要なかった。これは「大を連打すれば概ねよい」という学習を強化し、繊細な小／中／大の役割を弱くする。

また、地形に場所ごとの名前・距離差・安全床・戻り量の意図が乏しい。苔／根／バケツの絵は既にあるが、周囲に固有の跳躍問題が組み合わされていない。固定サイズの正確な点線予測も、力を身体で覚えるより既定の答えを選ぶ体験を支えやすい。これらは人間の面白さを断定する評価ではなく、新prototypeで検証する設計仮説である。

## 再設計の最初の拒否条件

- 最大チャージ・真上だけで主要区間を連続突破できる試験ステージにしない。
- 中チャージが主力、小チャージで発射位置を調整しないと本命が難しい場所、最大で天井／飛び過ぎが不利な場所を10〜20m試作に入れる。
- 空中左／右入力が発射後の速度を変えないことを通常入力で確認する。
- ミスは同じRUNに戻すが、少しの戻りと大きな戻りを別の地形で実証する。
- 再挑戦で同じ地形と風を学べる。ランダム配置や突然の未表示風を難しさの理由にしない。
- 自動到達の合格だけで「楽しい」「もう一回飛びたい」を人間合格にしない。
